# Hacktoberfest Weekend Challenge: Build for a Friend

Source: https://dev.to/challenges/hacktoberfest-weekend-2026-10-01 (read 4 Oct 2026)

## Dates

- Window opened: Fri 2 Oct 2026, 02:00 UTC
- **Submissions due: Mon 5 Oct 2026, 06:59 UTC = 08:59 Malta time**
- Winners announced: week of 5 Oct
- Challenge 1 of 5. A new one launches every Monday in October (5, 12, 19, 26),
  same prompt, new theme. Hub: https://dev.to/challenges/hf26

## Prompt

Build something with open-source AI at its core: an open-weight model, an
open-source agent harness or framework, local inference, or a mix. The open
pieces must be what makes the project work. The post must explain why open
innovation matters for what was built.

## Theme: Build for a Friend

Solve a real problem for one real person. Small is fine; it has to matter to
them. Bonus for actually handing it over and reporting what they said.

## Rules that can disqualify

- New project. Repo started and completed inside the window.
- Commits after the deadline must be noted in the README.
- Credit any non-trivial prior work or open-source code used.
- One submission per challenge. Teams up to four.
- English for prize eligibility. 18+.
- AI tools are allowed for building.

## Judging

1. Writing quality (weighted most heavily)
2. Relevance to the prompt and theme
3. Creativity
4. Technical execution
5. Use of partner technology (only for partner categories)

## Prizes

- Overall: $250 + DEV++ + winner badge
- Featured categories, $200 each: Render, TabPFN, Tinker, Arduino, DigitalOcean, **Gemma**
- Partner categories, $100 each: Backboard, ElevenLabs, Entire, GitHub Copilot,
  Mastra, MongoDB Atlas, Sentry Agent Tracing, SerpApi, Temporal, Tiger Data
- Completion badge for every valid submission
- Categories are opt-in: list them in the post's Prize Categories section. One
  submission can win only once.

## Submission

A DEV post from the official template (see `post.md`) with tags
`devchallenge`, `weekendchallenge`, `hf26challenge`. Needs: what was built and
for whom, a demo (deployed link or video), the code, how it was built, why open
innovation matters. Optional but favoured: the agent session (DevRelay or a link).
