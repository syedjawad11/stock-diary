Workers AI includes **10,000 neurons/day**, resetting at **00:00 UTC—02:00 Malta**. Paid overage is **$0.011 per 1,000 neurons**. Gemma 4 costs **$0.10/million input tokens and $0.30/million output tokens**. Illustratively, 1,000 input + 400 output tokens consumes about 20 neurons: roughly **500 calls/day within the allowance**, before retries and other account usage. This is a budget estimate, not a benchmark. [Cloudflare pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/)

D1 includes **5 GB storage** and ample included operations for this diary; incremental demo spend should be negligible. [D1 pricing](https://developers.cloudflare.com/d1/platform/pricing/)

For Render, use the free Hobby workspace with the smallest **paid web-service instance**, plus a **1 GB persistent disk**. The published web-service tier is **$7/month**, prorated; disk is **$0.25/GB/month**. Claim the promo immediately and verify its balance, expiry and coverage rather than assuming an amount. [Render pricing](https://render.com/pricing)

**SQLite must live under the disk mount**, for example `/var/data/diary.sqlite`. Paid compute alone does not preserve files. Free Render services cannot attach disks, sleep after 15 minutes, take about a minute to wake, and lose local files when restarting or redeploying. [Render persistence](https://render.com/docs/disks), [free-service limits](https://render.com/docs/free)

Atlas M0 offers durable free storage with a **512 MB limit**. It genuinely fits the MongoDB category, but adds credentials, network access configuration and a different persistence design. Prefer SQLite today. [Atlas free tier](https://www.mongodb.com/docs/atlas/tutorial/deploy-free-tier-cluster/), [storage limits](https://www.mongodb.com/docs/atlas/reference/faq/storage/)

**Keep both model modes. It is worth a bounded 30–45 minutes.** Proposed `model_adapter.py` exposes one operation such as `generate_structured(messages, schema)`:

- `MODEL_BACKEND=ollama`: local Gemma, local endpoint.
- `MODEL_BACKEND=cloudflare`: Workers AI REST endpoint; credentials stay server-side.
- Both normalize responses into the same Pydantic shapes from `models.py`; validate centrally, with at most one retry.

Keep transport differences inside that adapter. Do not add a model framework, automatic provider switching, or promise identical accuracy. Test each mode separately. Cloudflare documents direct Python REST calls for [Gemma 4](https://developers.cloudflare.com/workers-ai/models/gemma-4-26b-a4b-it/).

**FastAPI is the fastest maintainable choice for this Python-first builder.** A TypeScript Worker could deploy quickly, but costs more in unfamiliar debugging and weakens the shared local/hosted implementation. Cloudflare’s [Python Worker support](https://developers.cloudflare.com/workers/languages/python/) is real; I would still avoid learning its runtime today.

**Public-demo protection:**

- Server-generated random visitor ID in a signed, secure cookie; every ledger query is scoped to it.
- Seed each visitor with the same synthetic catalogue. “Reset my demo” affects only that visitor; expire abandoned sandboxes after 24 hours.
- Parse → preview → explicit confirm. Atomic save, unique confirmation ID to prevent double posting, and undo through a reversal.
- Reject unknown products, incompatible units and negative resulting stock. AI never writes SQL or computes balances.
- Start with **5 AI calls/minute and 30/day per session**, plus an IP limit and a persisted global daily call cap. Resetting stock must not reset quotas.
- Limit sentence length and output tokens; count retries against quotas. Show a clear busy/error state without saving anything.

Use one Render process/instance today. Keep a video alongside the link as evidence if inference temporarily fails.

Use a small, fixed catalogue with explicit units and bilingual aliases. Ambiguity produces a product selector, never a guessed posting. Questions map to three allowlisted operations: balance, low stock and today’s movements. Python supplies the figures; fixed bilingual templates render answers.

Use warm neutral backgrounds, dark text, one green primary button, large quantities and **44 px minimum touch targets**. Low stock needs text as well as colour.

For Urdu, set `lang="ur"` and RTL on Urdu sections; use `dir="auto"` for mixed-language input and isolate SKU/numeric fragments.
